3. (Tuỳ chọn) CNEE & NOTIFY PARTY — chỉ cho lô KHÔNG phải CN

Lô CN (factory=CN) luôn tự động điền Consignee/Notify Party theo đúng cửa hàng — không cần đụng vào phần này. Với các nước/factory khác (POP, SBGEAR, QIFENG, JION...), gõ vào 2 ô dưới đây 1 lần trước khi bấm chạy — tool sẽ tự điền thẳng vào file kết quả, khỏi phải sửa tay lại trong Excel mỗi lần. Để trống thì file sẽ có ghi chú nhắc điền tay.

Cần chọn: PDF (thư mục hoặc zip) + file DIM + Master Data.

Cách dùng

1) Chọn thư mục chứa toàn bộ PDF Packing List của 1 lô hàng (hoặc zip lại rồi upload file zip).
2) Chọn file DIM/khối lượng và file Master Data (SKU ↔ HS Code) tương ứng lô đó.
3) Nếu lô KHÔNG phải CN, có thể điền CNEE/Notify Party 1 lần ở mục 3 (tuỳ chọn) — lô CN thì bỏ qua, tự động rồi.
4) Bấm "Chạy OCR + Tách nhóm" — log xử lý hiện trực tiếp bên dưới.
5) Xong sẽ có 1 nút tải về 1 file .zip gồm: PL_Total.xlsx (4 sheet — Packing List + Match_Status (QC log nội bộ) + Raw_Data (mỗi dòng item 1 hàng không merge, đầy đủ audit trail kể cả DIM) + Audit_Summary (version parser, số liệu chạy, DIM detection method)), cùng thư mục PL_SPLIT_OUTPUT/ (tách theo Factory / CN Port / CN Store, kèm PL_SPLIT_CONTROL.csv và báo cáo đối soát). Tóm tắt kết quả (số PDF/package/item, quantity check, DIM match...) hiện ngay trên trang sau khi chạy xong, kèm nút tải diagnostic log.
Shipping Mark trong Packing List tự lấy theo tên file PDF (bỏ đuôi .pdf), trừ khi tool đọc được dòng "Shipping Mark:" thật trong PL thì dùng giá trị đó. OR #/SO Order # cũng được tool cố đọc từ PL (nếu có) — không đọc được thì để trống, không báo lỗi. PO No. / Invoice No. / 中国标签名称 vẫn để trống — điền tay sau.
Carton # nay được đánh theo đúng thứ tự nghiệp vụ (factory → tài liệu gốc → bản "_1"/"_2"... theo số, không còn sort theo tên file kiểu chữ cái) thay vì theo tên file, và được đánh riêng theo từng Store/lô hàng (vd: Kerry 6 carton → 1/6...6/6, Hangzhou 4 carton → 1/4...4/4 — không gộp chung thành 1/10...10/10). Mặc định tool xuất thêm 2 file Sublist theo carton (bật/tắt riêng từng file ở ô 1): PL_SPLIT_OUTPUT/05_SUBLIST/SUBLIST_TOTAL.pdf (khổ A5, 1 carton/trang — đây là output Sublist chính) và SUBLIST_TOTAL.xlsx (bản Excel, tuỳ chọn phụ). Carton hơn số item chứa được trên 1 trang/block sẽ tự tách "Continued" sang trang/block kế tiếp, không mất item nào.
OR List (tuỳ chọn) — upload file Excel có cột STORE/OR/SO ở mục 2 để tool tự điền OR #/SO Order # theo đúng Store (khớp theo Shipping Mark → tên file → nội dung Receiver, ưu tiên khớp chính xác trước khi thử mờ; trường hợp không chắc sẽ đánh dấu REVIEW thay vì tự đoán). OR #/SO # đọc được trực tiếp từ PL vẫn được ưu tiên hơn OR List. Không upload OR List thì tool vẫn chạy đầy đủ bình thường, không báo lỗi, không khoá nút chạy.
Parser core đã được audit lại và sửa nhiều lỗi table/text parsing + DIM matching so với bản notebook gốc, kèm bộ regression test trong repo (tools/pl-ocr-grouping/tests/). Số version thật của bản đang chạy trên trình duyệt của bạn hiện ngay trong ô tóm tắt phía trên sau khi bấm chạy — so số đó với lịch sử commit trên GitHub nếu cần xác minh. Trang này vẫn chạy 100% Python thật trong trình duyệt qua Pyodide, không upload PDF/DIM/Master Data lên server nào.
